# CodeCairn Memory Hub prototype

This directory freezes the read-only product prototype for CodeCairn's human
inspection surface. It uses example data shaped by current public contracts and
does not connect the browser to a CodeCairn installation.

The prototype has three views:

- `?view=memories&detail=content|source|evolution`
- `?view=recall&sample=admitted|abstained`
- `?view=system`

Memories is the default view. Recall is intentionally read-only: its two
examples show relevance admission and explicit unrelated-query abstention
without pretending to execute a service call.

The prototype does not provide a local CodeCairn HTTP adapter or API, a daemon,
authentication, remote sync, memory mutation, or evidence that recalled memory
improved an agent task.

## Current capability mapping

| Hub concept | Existing CodeCairn contract |
|---|---|
| Filterable memory page and lifecycle status | `CodeCairnApplication.list_memory_page`, MCP `list_memories` |
| Full memory and canonical resource URI | `CodeCairnApplication.get_memory`, MCP `get_memory` |
| Immutable lineage | CLI and MCP `memory_history` |
| Admitted or abstained recall explanation | CLI and MCP `recall` |
| Point-in-time system state | CLI and MCP `doctor` |

The CLI `list` and `memory show` commands remain useful inspection surfaces,
but they do not expose the page status, pagination cursor, or detail
`resource_uri`. The Hub model uses the existing service and MCP DTOs for those
fields rather than inventing a browser-only schema.

## Executable contract snapshot

[`fixtures/codecairn-contract.json`](fixtures/codecairn-contract.json) is
generated by an executable integration fixture. The generator exercises the
real CLI presentation, service layer, Markdown store, SQLite state, and
LanceDB projection in a temporary directory. It uses the repository's
deterministic offline retrieval adapter, so the check does not download or call
a production provider.

The snapshot covers CLI list, show, history, admitted recall, abstained recall,
and Doctor output, plus the public `MemoryPage` and `MemoryDetail` service/MCP
DTOs. It fixes the current renderer
`codecairn/typed-excerpt-context-v2`, `admission_trace`, and `relevance`
omission behavior.

This proves local contract integration. It does not prove a live
browser-to-runtime connection.

## Local development

```bash
npm ci
npm run dev
npm run check
```

Node.js `>=22.13.0` is required.

After an intentional CodeCairn contract change, regenerate the snapshot and
review its complete diff:

```bash
npm run contract:update
```

From the repository root, `make hub-check` runs the executable contract check,
Hub lint, production build, and rendered-page tests. The full `make check` gate
also includes the Hub UI checks.
