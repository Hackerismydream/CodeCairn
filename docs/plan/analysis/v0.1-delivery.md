# Version 0.1 Delivery Analysis

## Why this is a reduction release

The baseline already contains most low-level pieces—trace import, Markdown,
SQLite, outbox, LanceDB, recall, evaluation, and public evidence—but does not
form one small product loop. Historical memory types, an Evidence Gate without
a public producer, benchmark-specific paths, and large orchestration modules
make the implementation harder to learn while MCP, hooks, onboarding, and
memory evolution are absent.

Version 0.1 should exchange framework breadth for one complete path:

```text
agent trace -> four-type memory -> supersession -> active recall -> next agent
```

## Keep, replace, delete

### Keep

- strict Codex/Claude normalization and stable episode identity;
- system-derived Evidence Facts;
- Markdown/SQLite/outbox durability;
- Mini Cascade and provider identity rules;
- active portions of hierarchical retrieval;
- exact-repair and immutable evidence principles;
- the current public evidence verifier.

### Replace

- six historical public types with four;
- evidence-gated write orchestration with capture plus system-derived
  verification facets and no standalone verification operation;
- implicit active state with an Evolution Record projection;
- environment-only setup with typed config;
- CLI/HTTP product framing with CLI/MCP/hooks;
- protocol-generation evaluation CLI with four release commands.

### Delete

- Evidence Gate acceptance as a storage prerequisite;
- type-specific proposal/audit machinery that exists only for that gate;
- alternate retrieval modes not used by release or a frozen verifier;
- superseded LoCoMo execution generations from installable source;
- background-watcher and HTTP-parity assumptions;
- compatibility migration for pre-v0.1 runtime roots.

## Critical risks

### Historical evidence coupling

Deleting execution code may accidentally break `benchmark-v3` verification.
Task v01-000a first characterizes the verifier's actual reader dependencies,
then preserves only those readers before the domain changes. Verification of
4,411 checked-in files is a hard regression gate.

### Semantic availability

Complete capture cannot depend on an online model. Task v01-002 commits one
deterministic Task Experience first and represents optional semantic work as a
queue. Tests cover provider absence, provider failure, retry, and idempotency.

### Lifecycle/index mismatch

Supersession changes two searchable records. Task v01-003 uses one Write Intent
for the Memory/Evolution Markdown batch, then commits the Evolution mirror,
derived status, and both index-outbox revisions in one SQLite completion
transaction; rebuild derives the same statuses from Markdown.

### Hook schema drift

Client hooks change outside this repository. Task v01-007 pins fixture shapes,
validates installed configurations, preserves manual import as fallback, and
makes failures visible without blocking the client.

### Code reduction becoming a rewrite

Each task deletes the obsolete path after its replacement passes. There is no
long-lived dual-write mode. Public behavioral tests protect the small set of
contracts that survive.

The deterministic source counter and CI gate land in `v01-000a`. Core must be
at most 15,500 after `v01-001`, 11,500 after `v01-004`, and 10,000 after
`v01-007`; total must be at most 15,000 after `v01-008`.

## Merge and rollback

Every task is an independently reviewable commit or short commit stack based on
its completed dependency. If a task fails acceptance, it does not merge. Once a
new durable schema task merges, rollback means using a fresh runtime root and
the prior Git commit; pre-release state is not dual-written.

Historical evidence remains immutable and verifiable across this process.
