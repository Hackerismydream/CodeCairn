# Expose explicit memory access through MCP

## Objective

Let Codex and Claude Code recall, remember, inspect, import, and diagnose
CodeCairn through visible tool calls without duplicating product behavior.

## Paths

Primary:

- add `src/codecairn/entrypoints/mcp.py`
- `src/codecairn/service/application.py`
- `src/codecairn/bootstrap.py`
- `pyproject.toml`
- add `tests/test_mcp.py`
- `README.md`
- `docs/runtime/operations.md`

## Required changes

1. Add the stable official Python MCP SDK range `mcp>=1.27,<2` and register
   `codecairn-mcp` as a console script. MCP v2 migration is post-v0.1.
2. Build a stdio server over the same application facade as CLI.
3. Implement exactly seven tools:
   `recall`, `remember`, `list_memories`, `get_memory`, `memory_history`,
   `import_session`, and `doctor`.
4. Implement `codecairn://memory/{memory_id}`.
5. Match schemas, defaults, constraints, and error behavior in
   `agent-integration.md` and `schema-contract.md`.
6. Resolve root/namespace from configuration and server working directory;
   optional tool `repo_key` is an override.
7. Reject direct Task Experience creation through `remember`; require valid
   user-authored `source_fact_ids` for direct User Preference.
8. Return Markdown Recall Context plus a structured sidecar from `recall`.
9. Keep protocol stdout completely clean. Send bounded diagnostics to stderr or
   the runtime diagnostic store.
10. Translate typed application errors into concise MCP errors with remediation
    and no stack trace or secret.
11. Generate and check in JSON Schema snapshots for all seven tools and the
    resource. Enforce maximum lengths/result caps, opaque cursor encoding,
    resource URI escaping, cancellation, and the stable error envelope.

## Registration

Document and test the installed commands:

```bash
claude mcp add codecairn -- codecairn-mcp
codex mcp add codecairn -- codecairn-mcp
```

Do not edit client MCP settings automatically in this task.

## Verification

Use the SDK's in-process client/transport:

```bash
uv run pytest tests/test_mcp.py
make format
make check
```

Acceptance cases:

- list tool schemas and resource template;
- create Repository Knowledge and Work State directly;
- create User Preference with valid user-authored source and reject it without
  that source;
- import a fixture and recall its Task Experience;
- active and historical recall;
- get and history use the same IDs as CLI;
- unsafe resource ID/path;
- missing provider, stale index, foreign namespace, malformed input;
- concurrent reads and one write;
- captured stdout contains protocol frames only.

Run a packaged subprocess smoke that starts `codecairn-mcp`, initializes the
protocol, calls `doctor`, and shuts down cleanly.

## Exit criteria

- all seven tools and one resource pass through the shared service;
- no entrypoint-owned memory policy exists;
- stdout is protocol-clean under success and failure;
- CLI and MCP identity/status behavior agrees;
- all checks pass and line deltas are reported.
