# Version 0.1 Evaluation

CodeCairn has eight authoritative evaluation and release-gate commands:

```bash
make eval-smoke
make eval-scale
make eval-retrieval
make eval-locomo-200 HELP=1
make eval-locomo-full HELP=1
make eval-coding-ab HELP=1
make evidence-verify
make source-budget
```

The first three exercise current v0.1 behavior. `evidence-verify` preserves the
historical `benchmark-v3` artifact boundary. A HELP invocation is a resolved
paid-run plan, not a benchmark result.

## Offline gates

`eval-smoke` runs the maintained lifecycle, semantic, evolution, recall, MCP,
and hook acceptance tests in isolated temporary roots. It covers both trace
families, four memory types, Write Intent crash recovery, Supersession,
history/restore, active-only recall, MCP identity parity, and idempotent hook
capture. It makes no provider call and publishes no score.

`eval-scale` deterministically generates 500 Codex and 500 Claude sessions,
each with 100 normalized events. It imports all 1,000 sessions twice and
requires:

- 100,000 observed events;
- 1,000 stable Episodes and Task Experiences;
- zero additional Episode or Memory on repeat import.

With no `RUN_ID`, it uses a temporary root and prints the aggregate. Supplying
`RUN_ID=<immutable-id>` writes an exclusive manifest, outcomes file, and
aggregate under `benchmark_results/scale/<RUN_ID>`.

`eval-retrieval` loads the checked-in 20-memory suite with 100 positive and 20
unrelated queries through the current Memory Runtime, Mini Cascade, LanceDB,
Recall Engine, and context compiler. Its deterministic evaluation-only
embedding/reranking adapters are named in the protocol and cannot be selected
by product configuration. The gate requires Recall@5 at least 90%, provenance
coverage 100%, no superseded candidate leakage, P95 no greater than four
seconds, and hard-negative injection metrics at most 5%. It must not be
described as a DashScope or FastEmbed production-model score.

## Paid gates

The HELP form prints the exact selection, expected artifact path, current HEAD,
clean-worktree observation, provider roles, credentials, and spend boundary.
No provider is contacted.

A live LoCoMo command requires:

```bash
RUN_ID=<immutable-id> \
SPEND_ACK=YES \
CODECAIRN_EVAL_WORKERS=4 \
SPEND_CEILING_USD=<hard-ceiling> \
MAX_CALL_COST_USD=<provider-upper-bound> \
DATASET=benchmarks/locomo/data/locomo10.json \
make eval-locomo-200
```

`CODECAIRN_EVAL_WORKERS` accepts 1 through 8 and is recorded in the run
manifest. Use 4 unless the provider requires a lower concurrency limit.

The full target uses the same contract with `eval-locomo-full`. Before creating
the run, it verifies a clean commit, the frozen dataset digest, provider
configuration, and a worst-case reservation for every bounded answer/judge
attempt. Both provider roles cap completion output at 512 tokens, and the
caller-supplied per-call bound is recorded in the immutable manifest. Answer
and judge clients are distinct. Each provider call has an immutable
started/finished journal pair; missing completion is unknown spend, not a
retryable success. Reports are pure reducers.

Infrastructure failures remain explicit negative outcomes and make the command
fail after preserving its artifact. A failed-only repair set is generated by
`write_repair_selection`; `compose_repair` accepts it only when its IDs exactly
equal the base run's complete infrastructure-failure set and provider,
retrieval, dataset, and protocol contracts are unchanged.

Coding A/B uses the existing isolated runner and hidden verifier:

```bash
RUN_ID=<immutable-id> \
MODEL=<codex-model> \
SPEND_ACK=YES \
SPEND_CEILING_USD=<hard-ceiling> \
make eval-coding-ab
```

Missing Codex authentication or agent failure is infrastructure failure, not a
task pass or fail. The runner records the declared ceiling; because Codex CLI
has no hard-dollar flag, enforcement belongs to the configured provider
account limit and is stated explicitly in the manifest.

## Artifact and evidence boundary

Every persisted run is exclusive and binds `implementation_sha`, run ID,
protocol, input digests, provider identities, and budget. `benchmark_results/`
is ignored during iteration; release task v01-010 selects and checks in or
publishes the final digest-bound artifacts.

`make evidence-verify` defaults to `evidence/benchmark-v3` and uses only the
small historical reader/reducer. It proves that frozen inventory and
aggregates, not current v0.1 behavior. Override with
`EVIDENCE_BUNDLE=<path>` for a new selected bundle.

The release thresholds and implementation/evidence SHA relationship are in
[`../v0.1/evaluation-and-release.md`](../v0.1/evaluation-and-release.md).
